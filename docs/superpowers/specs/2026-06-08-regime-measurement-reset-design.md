# Regime Measurement Reset Design

Status: approved for implementation planning
Date: 2026-06-08

## Goal

Correct the measurement basis used by Onda C before any further regime
redesign, feature promotion, or Onda 3 work. The sprint resets Onda C from
"classifiability over whatever numeric model features are available" to
"classifiability over the causal meteorological morning-state matrix that Onda
2E already built for regime discovery."

The immediate purpose is to decide whether the current Onda C failure is a true
failure of the regime ontology or a failure of the benchmark instrument.

## Problem

The current Onda C report returns `KEEP_IN_REGIME_DESIGN_REVIEW` for all
methods. That result may be scientifically invalid because the benchmark can
fall back to arbitrary numeric model features when the expected meteorological
columns are absent.

The current classifiability module looks for names such as:

```text
wind_dir_deg, wind_speed, qnh_hpa, relh, dewpoint_depression,
precip_pre_cp_sum, cloud_cover_score, temp_slope_pre_cp
```

Those names do not match the physical cluster matrix already generated by Onda
2E:

```text
drct_sin_mean, drct_cos_mean, sknt_mean, qnh_hpa_mean, relh_mean,
dewpoint_depression_mean, precip_pre_cp_sum, cloud_cover_score_mean,
temp_slope_pre_cp
```

When the expected names are missing, `_get_numeric_features()` can select all
numeric columns outside a small exclusion list. That can mix lags, model-facing
features, timing priors, and other non-regime measurement columns into GMM/SOM
diagnostics. If this happens, Onda C is no longer measuring whether regimes are
physically classifiable.

## Decision

Implement a non-production `Regime Measurement Reset` sprint before any
v2.2 regime redesign.

The sprint must:

1. Use the physical Onda 2E cluster matrix as the default classifiability basis.
2. Audit and persist the exact columns used by each Onda C method.
3. Fail fast when a physical-regime benchmark cannot find enough approved
   meteorological columns.
4. Prevent the unrestricted numeric fallback from being used for physical
   regime promotion decisions.
5. Rerun Onda C and update the gate based on the corrected measurement basis.

This sprint does not assume that v2.1 is correct. It only ensures the test used
to judge v2.1 is valid.

## Scope

The sprint builds:

- a feature-basis audit artifact for Onda C;
- a strict classifiability feature selector for physical regime benchmarks;
- CLI support for loading `obs.parquet` and `labels.parquet` so Onda C can
  rebuild the physical matrix through the existing Onda 2E cluster-matrix path;
- diagnostics proving that GMM/SOM/Michelangeli ran on causal meteorological
  inputs;
- regenerated Onda C artifacts under `reports/regime-classifiability/`;
- documentation/gate updates recording whether the Onda C failure survives the
  measurement reset.

## Non-Scope

- No Onda 3 model training.
- No production classifier promotion.
- No overwrite of `data/features.parquet`.
- No new external data dependency.
- No feature promotion from the failed `FEXP-FOEHN-CONTINUOUS-001` probe.
- No v2.2 regime redesign in this sprint.
- No new Foehn physical score implementation in this sprint.

If the corrected Onda C still fails, v2.2 becomes the next sprint. It is not
implemented here.

## Inputs

Required Onda C inputs remain:

- `reports/regime-design/regime_candidate_assignments_v2.csv`
- `reports/regime-design/regime_candidate_assignments_v2_1.csv`
- `reports/onda2e/regime_design_candidate_v2.csv`
- `reports/regime-design/regime_candidate_v2_v21_comparison.csv`

Additional required inputs for the reset:

- `data/features.parquet`
- `data/labels.parquet`
- `data/obs.parquet`

The classifiability CLI must accept these as explicit paths. If `obs.parquet`
or `labels.parquet` is not supplied when running in physical-basis mode, the
command must fail with a clear error instead of silently falling back.

## Physical Feature Basis

The approved physical basis is:

```text
drct_sin_mean
drct_cos_mean
sknt_mean
qnh_hpa_mean
relh_mean
dewpoint_depression_mean
precip_pre_cp_sum
cloud_cover_score_mean
temp_slope_pre_cp
```

These columns are valid because they are derived from METAR observations in the
causal pre-CP window. Direction is represented by sine/cosine components, not a
raw circular degree value.

Outcome columns remain excluded:

```text
tmax_int, tmax_hour, remaining_warming, tmax_anomaly
```

Quarantined or model-facing columns remain excluded from physical
classifiability decisions:

```text
regime_label, regime_flags, foehn_score, tmax_dminus1,
late_warming_anomaly, timing priors, baseline/model diagnostics
```

## Output Artifacts

### `regime_classifiability_feature_basis_audit_v1.csv`

Required columns:

```text
feature,source,included_in_classifiability,required_for_physical_basis,
causal_availability,leakage_class,missing_rate,variance_status,
selection_reason,production_status
```

Rows must include every approved physical feature plus any rejected candidate
column inspected by the selector.

Allowed `leakage_class` values:

```text
causal_input, excluded_outcome, excluded_quarantined_label,
excluded_model_feature, excluded_identifier
```

### `regime_classifiability_feature_basis_audit_v1.md`

The markdown report must state:

- which basis mode was used;
- how many approved physical features were included;
- whether any fallback was attempted;
- whether the benchmark is valid for physical regime decisions;
- the exact next allowed action.

### Existing Onda C Artifacts

The reset still regenerates:

- `regime_classifiability_assignments_v1.csv`
- `regime_classifiability_metrics_v1.csv`
- `regime_classifiability_comparison_v1.csv`
- `regime_classifiability_diagnostics_v1.csv`

All rows must remain non-production:

- assignment rows: `production_status = EXPERIMENT_ONLY`
- diagnostics/comparison rows: `production_status = EXPERIMENT_ONLY`

## Diagnostics

Add these required diagnostics to `regime_classifiability_diagnostics_v1.csv`:

- `physical_feature_basis_loaded`
- `approved_physical_feature_count`
- `forbidden_numeric_fallback_not_used`
- `outcome_columns_excluded`
- `quarantined_labels_excluded`
- `obs_labels_features_join_valid`

Critical diagnostics must fail the run when violated:

- fewer than two approved physical features survive preprocessing;
- outcome columns are included;
- production rows are present;
- duplicate `(date_local, cp)` rows are introduced by rebuilding the physical
  matrix;
- Onda 3/model artifacts are produced.

## Gate Logic

The reset can produce three outcomes.

### `MEASUREMENT_INVALID`

Use when the physical feature basis cannot be built or audited. In this case,
Onda C cannot judge regimes, and any current Onda C decision must be treated as
not actionable.

### `READY_FOR_ONDA3_DESIGN_REVIEW`

Use only when:

- all critical diagnostics pass;
- Onda C runs on approved physical features;
- v2.1 has no dead protected macros;
- alternative methods do not materially contradict v2.1;
- classifiability and stability meet the Onda C thresholds.

This is still not production. It only unblocks Onda 3 design review.

### `KEEP_IN_REGIME_DESIGN_REVIEW`

Use when the physical basis is valid but classifiability/stability still fails.
This outcome triggers the next sprint: v2.2 regime redesign with calm/radiative
restored and evaluated against the same physical-basis Onda C.

## Implementation Notes

The existing `_build_cluster_matrix()` in `solarstorm/onda2e/_full_eda.py`
already produces the physical basis and should be reused rather than duplicated.

The classifiability module should expose a strict selector that consumes the
physical matrix and returns both:

- the numeric matrix used for GMM/SOM/Michelangeli;
- a feature-basis audit table.

The old unrestricted numeric fallback may remain only for explicitly named
exploratory/debug modes. It must not be used by the default
`regime-classifiability-benchmark` command.

## Testing

Required tests:

- physical feature selector includes the nine approved physical columns when
  available;
- selector rejects or flags outcome columns;
- selector rejects model-facing fallback columns;
- missing physical basis raises a clear error;
- CLI with `--obs-path`, `--labels-path`, and `--features-path` rebuilds the
  physical matrix;
- feature-basis audit CSV/MD are written;
- regenerated Onda C report states whether the measurement reset changed the
  decision;
- all artifacts remain `EXPERIMENT_ONLY`;
- no Onda 3/model artifact is written.

## Follow-Up Decision

After the reset:

1. If Onda C passes on the physical basis, proceed to Onda 3 design review.
2. If Onda C fails on the physical basis, write the v2.2 redesign spec:
   restore calm/radiative as a protected macro, keep NW continuum and southerly
   flow, and evaluate subtypes as modeling structure rather than macro truth.
3. If the measurement basis is invalid, fix data construction before judging
   regimes.

This sequence prevents further failed attempts from accumulating without first
proving that the regime benchmark is measuring the intended physical system.
